# 统一设置页 / 面板 UX 范式

这份文档记录插件设置页和面板的交互约定，并核对现有实现。各插件可独立安装，分别维护自己的页面代码。

## 必须覆盖的四条状态

任何会读写设置的页面都必须显式渲染这四种状态，不允许「点了没反应」：

| 状态 | 表现 | 约束 |
|---|---|---|
| 加载中 | 显示进度/骨架，禁止可误操作的提交 | 读设置超时要有上限（建议 10s），到期取消等待 |
| 保存中 | 禁用重复提交；草稿仍可继续编辑；旧响应不得覆盖新草稿 | 同一页面的保存按操作顺序执行 |
| 结果未定 | 显示「结果待核对」并**暂停后续自动保存**，保留草稿 | 超时 / 连接中断 / 响应损坏 / 服务器错误都归此类 |
| 失败可重试 | 明确失败原因 + 重试按钮 | 任何「副作用未知」都不得自动重试（见下） |

## 副作用铁律（沿用 `ops-lite/lib/outcome.js`）

保存是**有副作用**的操作。失败必须回答三件事：`effectState`（是否可能已写入）、`retry`（能否重试、改什么后）、
`nextAction`（下一步做什么）。**只要可能已写入，就报「先核对再重试」，绝不自动重放。**

## 视觉与可访问性

- 跟随宿主主题变量（`--dsw-alias-*`），不写死颜色。
- 窄窗可用：窄到单体宽度时控件换行而不是被裁切。
- 键盘可操作：`Esc` 取消本次编辑、`Enter` 提交；焦点不丢。
- 数字输入框「清空」= 恢复默认，不等于 `0`（`Number('')===0` 会把「超时」变成「立刻超时」，功能坏但界面正常）。

## 新插件自查清单

1. 读设置：超时上限 + 加载态；失败给重试，不抛裸错。
2. 写设置：按序、去重、旧响应不覆盖新草稿；超时/异常→「结果待核对」，不自动重试。
3. 数字字段：空 = 默认，不是 0。
4. 视觉：主题变量、窄窗换行、键盘可达。
5. 文案：用户可见中文进生成词典（`\u` 转义），源码 ASCII。
