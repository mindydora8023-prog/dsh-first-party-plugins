## 2. P2 —— 值得做（分插件）

### gmail
- **每封邮件重发 SELECT、逐条 FETCH**（`lib/imap.js:232/240/259/270`，`lib/tools.js:166-180/331-333`）：`collect()` 与 `gmail_thread` 对每个 uid 循环 `fetch()`，25 封预览 = 25 次 SELECT+FETCH 往返。→ 每操作 SELECT 一次；UID 合成逗号集用单条 `UID FETCH a,b,c` 一次取回。
- **握手后无读超时**（`lib/imap.js:46-60/85-90`，`lib/smtp.js`）：`openTls` 连上后 `setTimeout(0)`，此后 LOGIN/命令/`readReply` 全无上界，只靠宿主 timeout 兜底且无法清 socket → 保留 idle 超时或 deadline。
- **预览/读信抓整封含全部附件**（`lib/tools.js:109/170-176/278`）：摘要为取 300 字却下整封 20MB 附件 → 预览用 `BODY.PEEK[TEXT]<0.1024>`；`gmail_read` 未保存附件时只抓 HEADER+TEXT。
- **reader 大 literal O(n²) 拼接**（`lib/reader.js:20-22/70-77`）：每个 chunk 都 `Buffer.concat([buf,chunk])` → 改 chunk 数组累积、需要时一次拼接。
- **search 无界拉全量 UID 再排序**（`lib/imap.js:191-213`）：大邮箱全量入数组；可改 UID 区间/最小堆取最新 N。

### ops-lite（读热路径，均已核实行号）
- **越界守卫先整文件 split**（`lib/tools.js:113`）：`offset > body.split('\n').length && ... && offset !== 1` 左→右求值，**默认 offset=1 每次读都整文件 split 建数组**再被 `offset!==1` 丢弃 → 判断顺序改为 `offset !== 1 && ...`，或用 `window.lineCount` 事后判定。
- **预算按整文件计费**（`lib/tools.js:67-70/105/136/249`）：`estimatedCost=size*3+4096` 用 `info.size`、`spent` 用 `buffer.length`（整文件）；1MB 文件即使 `limit:10` 也按 ~3MB 计费顶爆 `callMaxBytes`，后续条目全 pending → 有 offset/limit 时按 `min(size, limit*maxLineLength*转义系数)+固定开销` 估上界，`spent` 按实际渲染窗口字节累加。
- **逐文件串行 I/O**（`lib/tools.js:243-253`）：`for..of await` 串行；`isConcurrencySafe:true` 下可 stat/read 受控并发（观测写入仍在真读时发生）。
- **二进制探测只扫前 8KiB**（`lib/access.js:137-138`）：8KiB 后的 NUL 会被当文本 → 全量 `indexOf(0)`。
- **OFFSET_OUT_OF_RANGE 与物理 lineCount 差一**（`lib/tools.js:113/117`）：随"是否以 LF 结尾"漂移 → 统一按物理行数判定。
- **死代码/重复**：`lib/render.js:136` `WRITE_RECOVERY` 零引用；`compact.js` 与 `render.js` 各一份等价 `record`/整数谓词 → 合并到一处。

### filekit
- **XLSX 每单元格每属性新建 RegExp**（`lib/xlsx.js:36-38`，调用 `127-129`）：大表约百万级 `new RegExp` → 模块级按名缓存正则。
- **ZIP 中央目录每次重扫**（`lib/zip.js:70-72`，`lib/xlsx.js:222-247` 一次读 5 个 entry → 遍历 5 遍）→ 拆 `parseCentralDirectory` 一次解析复用。
- **PDF 整文件 `toString('latin1')` 最多 3 份**（`lib/pdf.js:358/439/455`）→ 算一次复用或改 `Buffer.indexOf`；顺手删 `parseClassicXref:361-366` 只跑一次的死循环。
- **死模块 `lib/text.js`**（已核实：`buildWindow/formatWindow/decodeUtf8` 仅在 `lib/tools.js:18` 被 import，全仓无其它使用）→ 删 import，模块移出 `lib/`；同步清 package 的 `node --check lib/text.js`。
- **配置死键 / scanMaxBytes 未接线**（`lib/config.js:45-52`；`lib/zip.js:71` 64MB、`lib/pdf.js:8` 硬编码）：profile 想收紧解压上限无效 → 真透传或在文档确认后删键。
- **XLSX 单格远列引用可撑爆行宽**（`lib/xlsx.js:159-164/261/272`）：`r="XFD1"` 造超长稀疏数组并等长渲染 → 对 `columnIndex` 与渲染 `width` 设上限。
- **畸形文件未捕获 RangeError**（`lib/pdf.js:298-313/764-813` 递归无深度上限；`lib/docx.js:28-29` 码点未校验）→ 加深度上限、`cp<=0x10FFFF` 判断、把 `parseDocumentXml` 纳入 try。

### next-say
- **重绘 effect 无依赖数组，每次按键强制同步布局**（`client/client.template.js:620-640`，`paintGhost→place()` 用 `getBoundingClientRect/getComputedStyle`）→ 加依赖 `[enabled,phase,sessionId,ghostText,ghostPrefix]`。
- **热路径 `historyCompletion` 每键重算全池归一化**（`client.template.js:295-315`；`lib/match.js:57-59/130-138`）：≤200 条×2000 字×9 趟正则 → `historyEpoch` 变化时预归一化缓存。
- **设置 schema 宿主/客户端两份无同步**（`lib/config.js:19-50` vs `client.template.js:34-54`，已现 `pausedUntil` 漂移）→ build-client 内联或加 build-sync 断言。
- **挂载兜底与回合轮询双触发可能双计费**（`client.template.js:351-366` 与 `370-411`）→ 收敛单一触发/让兜底带 turn 供去重。
- **per-session Map 仅靠 `session/disposed` 清理**（`lib/index.js:67-79/140-149`）→ 加 LRU 上限。
- **死代码/临时注释**：`lib/index.js:623-624` 空 else、`471-472/566` "Removed before delivery" 观测注释。

### archived-sessions
- **并发状态写丢配置**（`lib/cleanup.js:83-110`）：`writeState` tmp 名固定 `${file}.${pid}.tmp`，`saveCleanupConfig`/`saveLastRun` 均"读后写"，可互相覆盖 → 模块级写锁 + tmp 名加随机、rename 加 ENOENT/EPERM 重试。
- **超时后提前放锁**（`lib/index.js:304/516`）：`withDeadline` 超时即释放队列/锁，但底层事务仍在 rename/setState，用户重试可能重叠 → 用"毒标记"保留 id 到底层 Promise settle 再解锁。
- **批量预检 O(ids×headers) 且串行 findLog**（`lib/index.js:362-376`，`planDeletion` 每次重建 `childIndex` `:76`）→ 一次建好 `childOf` 传入、findLog 受控并发。
- **`snapshotHeaders` 与 `scanArchived` 各建一遍 header 映射 + 串行 stat**（`lib/index.js:23-34`、`lib/cleanup.js:132-177`）→ 抽 `collectHeaders` 共享 + stat 小并发。

### session-meter
- **`writeStatus` 不建目录**（`lib/index.js:190-196/198-202`；`lib/state-dir.js:73-75` 只 join 不 mkdir；全插件无 `mkdirSync`）：干净 profile 上目标目录不存在 → 写入抛 ENOENT 被空 catch 吞掉，**诊断文件永不生成**。host.test 用 mkdtemp 掩盖了它 → 写前 `mkdirSync(dirname(statusFile),{recursive:true})`（与 task-radar/filekit 约定一致）。
- **每个取价请求都 `Object.keys()`+同步写状态文件**（`lib/index.js:237-238`，约 1.1 万键）→ 计数只在 refresh 成功时更新、writeStatus 节流/异步。
- **GET 在 stale 时同步 `await refresh()`**（`lib/index.js:221`）：离线时每次轮询被上游超时绑架约 20s → 立即用当前 state 应答，刷新留后台 + 退避窗。
- **价目缓存放开共享 `%TEMP%`、非原子写**（`lib/index.js:72-78/113-124`）→ 落 `statePath` 或按 URL 哈希隔离，tmp+rename 原子写。
- **`nameCandidates` 宿主/客户端各一份**（`lib/prices.js:108-127` vs `lib/client.js:467-486`）→ 抽 shared 或加 parity 测试。
- **README 状态路径过期**（`README.md:116` 仍写在插件目录）→ 改为 `%LOCALAPPDATA%\dsh-plugins\session-meter\...`。
- **缺 `shared-sync.test.mjs`**（其余四插件都有，`lib/state-dir.js` 已登记在 MANIFEST）→ 补一条。

### task-radar
- **首拉重放整段 journal**（`lib/client.js:186-211`，`watcher.lastAt=0`，`startWatcher` 立即 tick，循环对 `at>0` 全弹）：打开/刷新页面会把内存里积压的最多 24 条历史通知当新通知全弹；`208-211` 的基线兜底块因循环内已推进 lastAt 恒不生效 → 首次成功 tick 只做基线播种再 return（并改固化了该行为的 `test/client-load.test.mjs:107-127`）。
- **用毫秒时间戳做游标会丢同毫秒事件**（`lib/client.js:200/206`）→ host `pushJournal` 加单调 `seq`，client 比较 seq。
- **`tag:'task-radar-'+kind` 不带 session**（`lib/client.js:163-174`）→ 同 kind 新通知替换旧通知、多会话完成只见最后一条；tag 加 session+seq，多窗口用 BroadcastChannel/存储选主。
- **`states` Map 无上限且持有完整 session 对象**（`lib/index.js:299-306/382-384/419-425`）→ 只存轻量字段、idle 后 delete 或 WeakMap + 容量上限。
- **默认两通道全开 → 单事件双弹**（`lib/config.js:47-55`）→ 默认 `system.enabled=false` 或设置页显式提示互斥。
- **每条通知 fork 一个 PowerShell、无并发上限**（`lib/index.js:146-159/351`）→ 串行队列/≤2 并发（保留 timeout+SIGKILL+stdio ignore 的可杀契约）。
- **`cooldownMs` 设 0 被 `|| DEFAULT` 吞**（`lib/config.js:79`）→ 改显式判空让 0 生效；死代码 `dshHome()`(`index.js:47`)、`watcher.cfg`(`client.js:146/195`)。
