# 任务雷达

为 DeepSeek Harness 提供任务通知：Windows 原生 Toast 与浏览器系统通知两条通道，可分别开关。版本 0.2.2。没有任务在跑时，浏览器通知的轮询从 2.5 秒放宽到 12 秒；Windows Toast 仍由宿主直接发送，不靠这次轮询。

插件包含 Pasumao 通知引擎的改编与本工作区的配置、浏览器 journal、设置集成等开发。来源与适用 MIT 原文见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)，不声明全包独立原创。

## 当前功能

| 事件 | 默认开关 | 触发 |
|---|---|---|
| turnStart | 关 | 智能体进入运行状态 |
| finished | 开 | 活跃回合正常结束 |
| aborted | 开 | 中止、中断或阻断后结束 |
| error | 开 | 错误或输出上限后结束 |
| waiting | 开 | 运行中调用 ask_user_question；或运行中的智能体被关闭 |

默认只提醒根会话，按 `origin: subagent` 或正数委派深度过滤子代理；仅带历史父会话记录的普通分支仍视为根会话。通知正文带可解析的工作区和会话名称；摘要来自本次运行中已接收的用户指令，运行时上下文与技能注入不会覆盖摘要。运行开始时用户指令尚未入日志，开始通知使用通用任务文案，避免引用上一任务。问答工具返回或运行结束后清除等待状态。相同事件与会话受冷却时间限制，默认 4 秒；系统时钟回拨后重新建立冷却基准。

Windows 通道由宿主调用 PowerShell 5.1/WinRT，不要求浏览器页面保持前台；实际显示取决于操作系统通知设置。支持自定义 PNG 路径与 reminder 常驻选项。发送子进程有超时，不会无限等待。

浏览器通道需要通知权限和仍在运行的页面，以约 2.5 秒间隔轮询宿主内存 journal，页面隐藏时继续轮询，重新可见时立即补查。浏览器可能节流或冻结后台页面，因此通知时延与补查范围受浏览器和 24 条 journal 容量限制。单次轮询（含响应正文读取）上限 10 秒，超时后释放轮询锁；卸载时取消在途请求，迟到响应不会再发通知。点击浏览器通知会唤醒窗口，并尝试在应用中打开对应会话。Windows Toast 没有同等会话跳转接线。两个通道同时开启可能收到两条提醒。

同一浏览器、同源且共享存储的多个标签页，会在支持 Web Locks 与 localStorage 时协调浏览器通知，按日志代际和事件序号记录已显示凭据。首次打开页面只建立本页游标，不替其他页面消费事件；响应乱序也不会因共享最高序号跳过较早事件。凭据最多保留 4 代日志、每代 512 个序号，不含标题、正文或会话标识。历史凭据淘汰、页面在显示与写凭据之间崩溃、存储不可用或浏览器不支持协调时，可能重复提醒；这些情况保留单页通知能力。不同浏览器、端口或存储分区分别处理。

目前只有上述两个通道。旧文档所提 Webhook、飞书/钉钉/企微推送、HMAC 加签、密文接口和自定义分事件音效未在本版本实现；系统自身可能播放通知提示音。

## 安装与设置

参见[仓库安装说明](https://github.com/mindydora8023-prog/dsh-first-party-plugins#安装)。包名为 `dsh-plugin-task-radar`。需要 DSH 0.2.2-rc.3 或更新的兼容 0.2.x 版本；安装并重启宿主、刷新页面后，在设置中的“任务雷达”配置总开关、事件、通道、根会话过滤、冷却、摘要长度、标题前缀、图标及常驻选项。

设置加载时显示进度，失败后可直接重试。修改设置后点保存；请求进行中拦截重复提交，保存期间仍可继续编辑，新草稿不会被旧响应覆盖。保存或测试请求上限 10 秒；结果未确定时保留草稿并提示先核对，不会自动重试。若需重新打开设置核对，请先复制保留尚未保存的修改。通知权限已被浏览器阻止时显示设置指引；总开关关闭或配置尚未加载时，不会因普通点击弹出权限请求。

配置默认写入用户状态目录的 `dsh-plugins/task-radar/config.json`，可用 `DSH_PLUGIN_STATE_DIR` 或 `TASK_RADAR_CONFIG_FILE` 覆盖，不写入源码目录。保存采用独占临时文件与原子替换，只有写盘成功才更新活动配置；写盘失败时接口返回错误，继续使用原配置，修复目录或权限后可再次保存。

摘要长度为 1–4096 字符，默认 48；冷却为 0–86400 秒，默认 4 秒，0 表示关闭冷却。数字设置接受有限数值或非空数字字符串，超大有限值截到上限，异常类型与非有限值退回默认，保存后再次读取保持一致。

启动时读取配置只接受不超过 256 KiB 的普通文件，打开前后均核对文件属性，实际读取也有字节上限；异常文件退回默认配置，文件句柄始终关闭。

配置接口只接受 JSON 对象（直接配置或 `{ "config": {...} }` 包装）；空值、数组和标量返回 400，不重置配置。请求正文上限 256 KiB、总读取时限 10 秒，超限返回 413、读取超时返回 408；这些失败均发生在保存之前。客户端断开时停止收集正文并清理监听器。插件或路由卸载会取消在途配置请求，返回 503 `plugin-unloaded`，即使正文刚好读完也不会再保存。`HEAD /api/task-radar/radar` 仅返回响应头。

“测试已保存的 Windows 通知”按钮使用已保存的配置，当前只提交 Windows Toast 测试请求；它不模拟完整任务，也不向浏览器 journal 注入事件。请求返回成功不代表操作系统已实际显示通知。浏览器通道应授予权限后，用一次任务事件核对。

## 接口与访问

0.2.1 使用宿主统一 Connection 的三个精确接口：`GET/HEAD /api/task-radar/radar`、`POST /api/task-radar/config`、`POST /api/task-radar/test`。接口复用宿主浏览器认证、Host/Origin 校验、owner 身份限制和桌面请求转发；原先裸露的 `/task-radar/*` 路由已移除。不需要独立浏览器服务的场景仍可运行原生通知。

直接打开未带宿主登录态的 HTTP 地址会返回 401，应从应用提供的已认证入口进入。升级已安装插件需要宿主重新加载模块，页面也需刷新，旧页面请求旧接口会显示加载失败。

## 运行数据

宿主内存最多保存 24 条通知 journal，包含标题、摘要、位置和会话标识；每条有递增序号，每次加载插件有独立日志代际，用于区分同毫秒事件、时钟回拨和宿主重启。重启后历史消失，浏览器通过同源接口读取，页面首次成功读取只定位游标、不重放此前通知。插件不向第三方推送服务上传这些数据。真实通知可能展示任务摘要，请按需关闭通道或调整摘要长度。

## 开发与验证

```sh
npm test
npm run build
npm run check:icons
```

测试使用临时目录、宿主与浏览器替身、可替换的通知发送器，不发送真实系统通知，不访问真实账户或外部网络。HTTP 集成测试仅在 127.0.0.1 的临时端口验证超限响应与客户端断开，结束后关闭服务器与连接。Windows 另有真实 PowerShell 语法解析测试，仅解析脚本而不执行通知；其他平台明确跳过该用例。实际 Windows 通知中心与真实浏览器显示属于手动验证，不由替身测试冒充。

安装版 Connection/Cordis 集成测试依赖 `DSH_INSTALL_DIR` 指向当前安装包；在 DSH 内运行会验证真实认证、owner/non-owner 和卸载行为，普通独立检出未配置此路径时会明确跳过此项。凭据只用内存替身，网络只使用临时回环端口。

0.2.1 修复安装版 HTTP 桥接对 GET/HEAD 的正文模式要求：日志读取使用 buffered，配置与测试提交使用 streaming；浏览器客户端也支持宿主提供的 Fetch 载体。已用真实桌面设置页验证加载、保存及深浅主题与窄窗布局。

0.2.0 包含通知游标与多标签去重、保存事务、请求上界、设置页并发编辑保护、统一认证接口和宿主主题变量适配。更早的 0.1.2 修复原生脚本把 JavaScript 的引号转义误用到 PowerShell XML 字符串的问题，改用 PowerShell 单引号拼接和 SecurityElement XML 转义，并开启遇错终止，使进程退出日志可以反映执行失败。

图标源稿与重建入口：

```sh
node tools/build-icons.mjs
node tools/build-icons.mjs --check
```

两种图标由同一几何定义生成，Node.js 标准库即可重建；运行包同时包含 SVG、PNG、生成器和完整许可证。修改生成物前先改源稿。
